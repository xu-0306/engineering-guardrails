# UI Reference Fidelity

將已選定的設計落實為可用介面。保留參考稿的資訊主次、空間關係與操作意圖，以使用者眼前的結果判定完成。技能只約束本次授權範圍，不增加產品功能、固定框架、強制文件或額外批准階段。

## 確認本次要保留的設計

- 直接查看使用者提供或已選定的圖片、HTML、設計檔及相關實作。歷史摘要只能協助定位；不能代替看原稿，也不能把歷史「完成」當成本次驗證。
- 以最新明確要求為準，分清哪些部分要求照稿、哪些允許調整。已有選擇就沿用；多份原稿只在存在實質衝突時澄清。缺少原稿時先定位可用資料，明示尚不能驗證還原度，不自行宣稱看過。
- 擷取會影響本次改動的約束：主要內容與操作、區域比例、字級層級、對齊與留白、閱讀密度、側欄行為、捲動位置、品牌或角色元素。不要把任何案例的尺寸或斷點變成通用標準。
- 可直接沿用的模板結構、樣式、素材優先沿用；不要只讀出配色再自行重畫。假資料、失效連結、未實作功能與不安全程式須辨別處理，不能為外觀相似偽造產品能力。
- 靜態圖沒有定義點擊後、窄視窗或等待狀態。依既定產品行為與上下文補齊，必要的推論簡短說明；不能以此否定圖中已清楚表達的布局。

小修正在工作說明中記住必要約束即可；較大改版可沿用現有計畫記錄，不另建平行規格。使用者只要求分析時，止於有依據的分析。

## 將操作接成完整流程

對受影響操作確認：使用者想完成什麼 → 在哪裡操作 → 立即看見什麼 → 接下來可以做什麼。讓按鈕名稱、結果位置及實際效果一致。

- 非同步操作在原操作附近或適當工作區呈現等待、結果與可恢復錯誤；防止會造成問題的重複提交。資料已載入、DOM 已建立或 API 成功，都不等於使用者已看見結果。
- 「閱讀」須讓正文可立即找到與開始閱讀；「重試」須執行所指的重試，不能只重新整理狀態。可能重複外部副作用的操作沿用產品的授權與重送保護。
- 頁面更新、切換、收合與串流不得任意丟失正在編輯或閱讀的內容。只在操作意圖需要時移動焦點或捲動，背景更新不搶走位置。
- 判斷側欄是並排工作區還是模態介面；不要因套用現成抽屜，就默默阻斷使用者原本需要繼續操作的主區。依實際寬度與操作需求決定行為。
- 內部資料欄位不直接決定畫面主次。使用者需要的技術資訊應解釋用途、單位與後果；原始 trace 等詳細證據可漸進展開，保留必要能力。

## 實作時保住整體體驗

- 先看受影響元件、呼叫者、共用 CSS、狀態及既有測試，再選最小完整修改。沿用框架與元件；只有具體障礙證明必要時才考慮替換。
- 「最小」指滿足要求所需的修改；必要的 DOM 重排、容器調整與狀態接線不能因改動較大而省略。也不為單一問題重寫全站或建立新設計系統。
- 修局部問題時維持該流程的既有核心要求。例如解除裁切後仍要能繼續輸入；壓縮頁首不能悄悄移除已要求的角色；圖示看起來小仍可保有適合的點擊區與可存取名稱。
- 多頁改版先在一個有代表性的完整頁面確認共用布局與互動，再套用其餘頁面；單一按鈕或文案調整不需要這個階段。無需因此增加一次使用者批准。
- 如果任務已採分工，交接參考稿位置、必要視覺／行為約束及共用元件責任；整合者核對完整流程與跨頁一致性。分工完成不能替代整合驗收；此技能本身不要求或授權派出代理。

## 驗證使用者實際得到的結果

依改動挑選必要證據，不固定測試數、尺寸矩陣或全產品回歸。

**外觀：** 對受影響畫面，以相同或可比較的 CSS viewport、縮放、內容密度與操作狀態查看原稿和成品。先看主次、區域比例、對齊與閱讀密度，再看細節；截圖存在或無溢出不能代表還原完成。合成資料可用，但須涵蓋相關長文／空態，不能用短內容掩蓋問題或把缺素材的 fixture 當成正式外觀。像素差分僅在適合且需要時使用，不設定任意相似度門檻。

**操作：** 走一遍本次修改的實際使用路徑，確認可見結果與下一步。對互動缺陷，優先用實際點擊、鍵盤、滾輪或觸控驗證；程式直接呼叫 handler 或設定值只能證明相應邏輯。

- 捲動案例須有足夠長的內容，確認目標容器實際位移且預期內容進入視野；保存位置測試先證明初始位置非零且可捲動，避免零值不變也通過。直接設定 `scrollTop` 不能證明滾輪可用。
- 非同步案例確認等待期間與失敗時的結果在眼前；「文字存在於 DOM」不是可見性斷言。位置與焦點檢查配合實際操作意圖，不強制所有成功都移焦點。
- 側欄、彈窗及固定輸入區的變更，驗證受影響視窗下的主要操作可達、正文可讀，以及關閉後可繼續原流程。
- 保留與改動相關的資料保護、鍵盤、焦點及輸入法行為。合成事件只證明相應邏輯，不能冒充真實裝置或 OS 輸入法驗證。

**交付入口：** 如果交付涉及建置、桌面包或快取更新，核對使用者實際入口載入的版本。出現「改了仍沒變」時，先排查入口、產物及快取，不直接疊加 CSS。測試新瀏覽器不能代替既有使用者的升級路徑；純原始碼任務不擴張為部署。

## 完成與交接

- 清楚區分已驗證的功能、已對照的外觀、已走過的操作與未測限制。測試總數、打包成功或其他代理的結論都不能單獨證明 UI/UX 完成。
- 有必要差異就繼續修正；若因環境無法驗證，交付已完成部分並準確標示缺口，不能改寫成通過。無關改善不阻擋交付，不必為驗收擴大資料或外部操作權限。
- 在既有交接處保留重要設計決策、尚未解決的必要差異及證據位置，避免只留下「已完成」。使用者已接受的取捨仍有效，不從舊報告復活已取消的需求。
- 必要工作與驗證完成即交付。此技能降低遺漏風險，不能保證自動觸發、視覺判斷或所有裝置行為永遠正確。
